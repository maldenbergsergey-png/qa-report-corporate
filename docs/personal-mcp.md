# Личное MCP-подключение

В **Профиль → MCP-сервер → Мой личный MCP** создайте токен, выберите
клиент и выполните команду подключения. Node.js 22+ нужен по-прежнему.
Можно иметь три активных токена: отдельные названия, чтение либо чтение и
заполнение, сроки 30/90/365 дней или до отзыва. Секрет показывается один раз;
не сохраняйте его в репозитории. Истёкшие и отозванные токены не занимают лимит.
Список показывает срок, права и последнее использование. Отзыв немедленно
закрывает последующие запросы и ещё не выданные браузеру пакеты.

## Найти и заполнить чек-лист

Попросите ассистента: «Найди чек-листы по SHOP-123». Поиск охватывает ваши
публикации, личные облачные копии и историю подключённого браузера. Проект и
предварительная публикация для локального поиска не требуются. Поиск принимает
ключ Jira/EVA или название; результаты содержат ссылку, окружение, дату и источник.
При нескольких совпадениях уточните нужный чек-лист.

Для локальной истории нажмите **Подключить этот браузер**. Это явное разрешение
на доступ к локальным чек-листам для текущего аккаунта. Оставьте вкладку открытой,
окно настроек можно закрыть. MCP выбирает отчёт по ссылке или результату поиска
и автоматически включает его приём: копировать временные ключи не требуется.
Поддерживаются ячейки, статусы, поля, полная замена по явному поручению и вложения
из выбранной папки. Только результат `saved` подтверждает запись в браузере.
Устаревшие hashes отклоняются; другой отчёт при этом не меняется.

Опубликованные отчёты и облачные копии доступны своему владельцу для чтения без
браузера. Для заполнения нужен исходный чек-лист в подключённой вкладке.
Публикация является снимком: после правок обновите её обычным способом.
При передаче ссылки на собственную публикацию MCP может найти её исходный
чек-лист в подключённом браузере по сохранённой связи публикации. Переданная
ссылка на чужой отчёт не расширяет права личного токена.

**Отключить этот браузер**, выход и смена аккаунта закрывают локальную связь.
Вкладка без связи исключается из поиска после короткого таймаута (30 секунд).
Разрешение на этот браузер сохраняется в текущей вкладке для того же аккаунта;
токены сохраняются независимо от вкладки и перезапуска сервера. Если одинаковый
чек-лист доступен в нескольких вкладках, выберите `browserId` из поиска.

## Границы доступа

Это доступ своего ассистента к своему аккаунту, отдельно от проектных ключей
разработчиков. Регистрация разработчиков и выдача им прав на аккаунты не добавлены.
Будущий доступ разработчиков должен использовать собственные разрешения; личный
токен владельца не следует передавать получателю отчёта.

Управление: `/api/mcp/personal-tokens` GET/POST, `/<id>` DELETE.
Локальная связь: `/api/mcp/personal-workspaces`, только с существующим входом
аккаунта и защитой записи конкретной версии. Каталог содержит метаданные,
до 1000 чек-листов; до 5 подключённых вкладок на аккаунт. Контекст выбранного
чек-листа передаётся через существующий ограниченный временный буфер, а не
публикуется автоматически. Служебный ключ временной сессии не передаётся MCP.

MCP использует отдельный `/api/mcp/personal/`: поиск `reports` и строго
ограниченные `report/context`, `report/batches`, `report/batches/<id>`,
`report/files/<id>`. Личный Bearer-токен передаётся в заголовке, хранится только
SHA-256. Вход, облачная запись, публикация, Jira/EVA, настройки и администрирование
через этот токен недоступны. Корпоративная и публичная авторизация не смешиваются.
Отдельная проверка после чтения тела и перед выдачей пакета браузеру закрывает
отзыв токена во время ожидания. Приём личного MCP нельзя использовать через
обычный producer URL в обход личного токена.

Клиент хранит `QA_REPORT_PERSONAL_URL` и `QA_REPORT_PERSONAL_TOKEN` в личной
конфигурации. Используется тот же пакет stdio MCP со стабильным URL скачивания;
отдельного хостинга нет. Каждый вызов содержит явный `reportUrl`, при необходимости
`browserId`; параллельные вызовы разных отчётов не меняют общий выбранный отчёт.

Проверки: `npm run check`, `npm test`, `node tests/personal-mcp.browser.cjs`
с Playwright в `QA_REPORT_PLAYWRIGHT`. Используются только синтетические данные.
