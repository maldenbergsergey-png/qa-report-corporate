# Подключение ИИ через MCP

В профиле откройте **MCP-сервер**:

- **Личный MCP** — личные токены. Создайте токен, выберите ассистента и нажмите
  «Скопировать запрос». Вставьте запрос в локальный чат Codex или Claude Code:
  он содержит точные параметры сервера и токен. Ассистенту нужны права на личные
  настройки; он сообщит, если требуется разрешение или перезапуск MCP.
- **Для разработчика** — запрос установки единого MCP для опубликованных ссылок и назначения проектов сотрудникам.

«Настройки подключения» содержит ручные форматы, систему и папку вложений.
Секрет остаётся в запросе и личной конфигурации; не публикуйте запрос.
Это локальный stdio MCP, Node.js 22+ и доступ к загрузке пакета нужны по-прежнему.
Обычный чат без инструментов настройки не может установить сервер сам.

Разовый приём сохранён в сворачиваемом пункте **Разовое подключение к чек-листу**
на вкладке «Личный MCP». Сначала включите приём кнопкой AI в нужном чек-листе,
затем выберите его в этом пункте. Токен аккаунта для этого не требуется.

Подробности: [личные токены](personal-mcp.md), [ключ проекта](project-mcp.md).


## Для QA

1. Откройте нужный чек-лист и включите «Приём результатов от ИИ» кнопкой **AI**.
2. Откройте в профиле **MCP-сервер → Личный MCP → Разовое подключение к чек-листу** и явно выберите нужный отчёт
   из списка включённых приёмов. В списке видны задача, короткий ID и срок доступа.
   Отчёт не выбирается автоматически, даже если активен только один приём.
   Если приёмов нет, окно показывает инструкцию, без перехода к случайному отчёту.
3. Установите Node.js 22+ один раз, если его ещё нет. Выберите Codex или Claude Code
   и свою систему, скопируйте команду и выполните её в личном терминале.
   На Windows используется PowerShell. Клонировать репозиторий не нужно.
4. Откройте новый чат ассистента и проверьте сервер командой `/mcp`.
   Попросите прочитать текущий чек-лист и внести нужные результаты.

Для другого MCP-клиента выберите «Другой клиент (JSON)» и добавьте сервер
в личные настройки, сохраняя остальные подключения. В Codex также доступен
вариант ручного TOML с увеличенным таймаутом запуска. Формат JSON подходит
только клиентам с поддержкой локального stdio MCP и раздела `mcpServers`;
названия полей других клиентов могут отличаться.

В раскрывающемся пункте «Доступ к вложениям» можно указать абсолютный путь
к папке скриншотов/логов. Сервер сможет читать для загрузки только обычные
файлы внутри этой папки; выход через символическую ссылку запрещён.
Без пути доступны текст и статусы, инструмент загрузки не публикуется.

Оставьте вкладку QA Report открытой. Подключение относится к одному выбранному
чек-листу и действует максимум 5 часов с момента включения приёма. Остановка,
истечение срока и перезапуск сервера закрывают доступ. При повторном включении
приёма скопируйте новую команду. Получение `pending` ещё не означает сохранение:
ассистент проверяет операцию до `saved` или `rejected`.

## Для получателя отчёта

Откройте опубликованный отчёт и нажмите **AI**, либо в профиле выберите **MCP-сервер → Для разработчика → Скопировать запрос**. Вставьте запрос в чат своего локального ассистента с доступом к настройкам MCP. При первой установке ассистент скачает файл с указанной контрольной суммой и зарегистрирует его в личных настройках. Подключение использует MCP вашего ИИ-клиента и Node.js 22+. Отдельное приложение QA Report Connect для него не требуется. Если клиент попросит перезапуск, откройте новый чат.

Отправьте ассистенту полную ссылку на отчёт. Для следующего отчёта достаточно ещё одной ссылки. При первом обращении к другой установке ассистент добавляет её точный адрес в личные настройки устройства с вашего ведома. Ранее опубликованные ссылки также работают в установках с прежним пакетом MCP и доступом по ссылке. Каждый запрос идёт напрямую по адресу выбранной установки. Для работы с закрытой сетью подключите соответствующий VPN.

Инструмент `qa_report_read` принимает ссылку и возвращает `reportRef`. Передавайте этот идентификатор в `qa_report_save_answer` и `qa_report_read_text_attachment`. После перезапуска MCP прочтите нужную ссылку заново.

`qa_report_connect` — инструмент MCP для подтверждения входа на сайте отчётов. Для закрытой установки ассистент вызывает его с адресом сайта. Откройте предложенную страницу, войдите через AD и введите код из своего чата. Код действует пять минут. Подтверждение привязано к текущей корпоративной сессии. После выхода или истечения сессии повторите подтверждение с тем же установленным MCP. Поиск через `qa_report_list_reports` работает в проектах, назначенных сотруднику. В качестве `site` указывайте только выбранную установку.

Клиент передаёт ключ устройства в `X-QA-Developer-Device`, а ключ отчёта в `X-QA-Report-Token`. Оба заголовка разбираются обработчиками QA Report после штатной очистки `Authorization` на прокси.

Автор управляет назначениями в профиле на вкладке «Для разработчика». Укажите корпоративный email, выберите проект или вставьте ссылку на его задачу в Jira или Eva. Можно выдать доступ к будущим публикациям до выхода первого отчёта. У каждого назначения свой срок 30 дней и право просмотра или ответа. Повторная выдача обновляет права и срок. Отзыв проекта сразу исключает его из поиска. Права отдельно переданной ссылки действуют по условиям самой публикации.

## Один сервер, разные полномочия

| Подключение | Что доступно | Граница доступа |
| --- | --- | --- |
| Личный токен | Поиск своих чек-листов, чтение, заполнение через подключённый браузер | Аккаунт, выбранные права и срок токена |
| QA | Чек-лист, результаты, поля, загрузка файлов из выбранной папки | Один включённый приём |
| Получатель | Замечания, статус исправления, комментарий, текстовые вложения | Одна общая ссылка и её права |
| Разработчик с ключом проекта | Поиск опубликованных отчётов, чтение и ответы по разрешениям ключа | Публикации выдавшего ключ автора в одном проекте и трекере, 30 дней |

Пакет для QA и прежних разовых или проектных настроек содержит свои режимы. Выбор определяется подключением,
а не просьбой ассистента: режимы нельзя смешивать в одном экземпляре MCP.
Роль получателя не открывает инструменты редактирования QA.

## Размещение и запуск

Отдельный хостинг, открытый порт, публикация в npm и ручной запуск процесса
не требуются. Уже работающий сервер QA Report отдаёт пакет
`/downloads/qa-report-mcp.tgz`, а `/api/mcp/package` сообщает его актуальный
адрес с версией содержимого. Пакет включает только два публичных MCP-скрипта
и минимальный manifest с зафиксированными зависимостями. Данные отчётов,
настройки развёртывания и секреты в архив не входят.

Общее подключение разработчика запускает локальную копию `/downloads/qa-report-developer.cjs` через Node с аргументом `--links`. Поле `developerUrl` в `/api/mcp/package` содержит SHA-256 файла. Запрос установки просит проверить хеш до запуска. Для добавления сайта используется `node <установленный-файл> --trust <адрес-установки>`. Ключ устройства хранится отдельно для каждого адреса в личной папке `~/.qa-report/developer-mcp/sites`. Установленному файлу доступны стандартные модули Node. Доступ к npm и серверу первой установки при последующих запусках не требуется.

Для разовых настроек и проектного ключа клиент автоматически запускает пакет через `npx --yes --ignore-scripts`.
Для первой загрузки необходим доступ к серверу отчёта и npm. Поэтому Node.js
на компьютере пользователя пока требуется. Это локальный stdio MCP,
не удалённый HTTP MCP. Вариант без Node.js потребует отдельно реализовать
сетевой транспорт и подходящую авторизацию клиентов.

Команда сохраняет ключ в личных настройках клиента и может остаться в истории
терминала. Не отправляйте её в общие чаты и не добавляйте в репозиторий.
После обновления сервера, если пакет больше не скачивается или первый запуск
не укладывается в таймаут, заново откройте настройку, скопируйте подключение
и перезапустите его. Ручной вариант Codex задаёт `startup_timeout_sec = 120`.

Команды сверены с [OpenAI Docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
и [документацией Claude Code](https://code.claude.com/docs/en/mcp).

Проектный доступ разработчика на 30 дней без настройки на каждый отчёт:
[ключ проекта](project-mcp.md).

Личное подключение аккаунта с поиском чек-листов и работой через браузер:
[личные MCP-токены](personal-mcp.md).

Сценарий установки сверён с [OpenAI Docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
