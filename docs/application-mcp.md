# MCP выбранного отчёта

Подключение описано в [инструкции MCP](mcp-setup.md). Один локальный сервер
публикует инструменты только выбранной роли. QA использует действующий
временный приём, созданный после корпоративного входа и проверки CSRF.

Инструменты QA: `qa_report_capabilities`, `qa_report_get_context`,
`qa_report_update_cells`, `qa_report_update_metadata`,
`qa_report_replace_checklist`, `qa_report_get_operation`.
`qa_report_upload_attachment` доступен только с явно выбранной папкой.
Защита по hashes, атомарность пакета, идемпотентность operationId и
подтверждение `saved` сохраняются. Полная замена требует явного поручения
и `confirmReplace: true`. Вкладка редактора должна оставаться открытой.

Получатель использует инструменты чтения опубликованного отчёта,
текстовых вложений и сохранения ответа. Его временное MCP-подключение
выдаётся после корпоративного входа с CSRF, относится к одной публикации
и истекает не позднее сессии. Read-only ссылка не получает права отвечать.
Ревизия из последнего чтения защищает от перезаписи чужих ответов.
Статус QA не меняется.

Личный токен отдельно предоставляет поиск и выбор своих чек-листов, включая
локальную историю подключённого браузера. Создание отчётов, экспорт,
публикацию и управление интеграциями через MCP. Папка вложений не даёт
произвольного доступа к файлам компьютера. Текст отчёта и вложения
считаются данными, а не инструкциями модели.

Проектный доступ разработчика на 30 дней без настройки на каждый отчёт:
[ключ проекта](project-mcp.md).

Личное подключение аккаунта с поиском чек-листов и работой через браузер:
[личные MCP-токены](personal-mcp.md).
