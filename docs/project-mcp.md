# Проекты разработчика

## Назначение сотруднику

В «Профиль → MCP-сервер → Для разработчика» укажите корпоративный email сотрудника. Выберите проект или вставьте полную ссылку на его задачу в Jira или Eva. Нажмите «Выдать доступ». По умолчанию сотрудник может читать замечания и отвечать. Каждое назначение действует 30 дней и распространяется на существующие и будущие публикации выдавшего его автора.

Добавить второй проект и отозвать первый можно в этом же окне. Сотрудник использует одно локальное подключение. Вход подтверждается кодом из чата в браузере и заканчивается с корпоративной сессией. После подтверждения он может искать по ключу задачи среди назначений разных авторов. [Подключение сотрудника](mcp-setup.md).

## Ключ на один проект

Автор создаёт ключ в **Профиль → MCP-сервер → Для разработчика**.
Выберите проект и трекер, задайте название, например имя команды, при необходимости
включите «Только чтение» и нажмите «Создать ключ».
Выберите ассистента разработчика и передайте ему запрос подключения лично.
По умолчанию запрос вставляется в чат Codex или Claude Code; ручная конфигурация
доступна в «Настройки подключения».
Для Codex и Claude Code достаточно выполнить команду; для других клиентов есть JSON.
Node.js 22+ требуется по-прежнему, клонировать репозиторий не нужно.

Ключ показывается только при создании. После закрытия окна получить тот же
секрет повторно нельзя: создайте новый ключ и отзовите потерянный.
В списке «Выданные ключи» видны проект, трекер, разрешения и срок действия.
«Отозвать» немедленно прекращает дальнейшие обращения по этому ключу.
Можно выдать отдельные ключи разным разработчикам; максимум 20 активных на автора.

## Что открывает ключ

- Только опубликованные и не отозванные отчёты аккаунта, выдавшего ключ.
- Только один проект на одном трекере. Проект определяется по полной ссылке
  на задачу, включая тип трекера, адрес установки с её путём и код проекта.
  Одинаковый код на другом трекере не входит в доступ.
- Старые и будущие публикации этого автора, соответствующие выбранному проекту.
  Локальные черновики, личное облако и публикации других авторов не открываются.
- Чтение замечаний и текстовых вложений; при разрешённых ответах — статус
  исправления и комментарий по пунктам. Результаты QA не изменяются.

В списке проектов нужны ваши публикации с полной ссылкой на задачу. Один только
код вроде `QA-123` не определяет трекер и не используется для выдачи доступа.
Для отчётов нескольких авторов нужны отдельные ключи каждого автора.
Отзыв публикации исключает её из доступа. Обновлённая публикация с другой
задачей/проектом проверяется по текущей ссылке, а не по прежнему расположению.

Ключ действует **30 дней с момента создания**, независимо от открытой вкладки,
выхода из профиля и перезапуска сервера. Это отдельный вид доступа для опубликованных отчётов проекта. Вход и остальные API он не заменяет.

## Для разработчика

Подключите MCP один раз. Например, попросите ассистента:

> Найди отчёт по задаче QA-123 в доступном проекте, прочитай замечания и исправь
> соответствующие места в коде. После выполненных исправлений обнови ответы.

Ассистент сначала использует `qa_report_list_reports` (поиск `query`, страницы
`offset`/`limit`, продолжение `nextOffset`), затем передаёт явный `reportId`
в `qa_report_read`, `qa_report_save_answer` и `qa_report_read_text_attachment`.
Одно подключение обслуживает несколько отчётов; ID пунктов и ревизии нельзя
переносить между ними. При нескольких подходящих отчётах уточните окружение
или дату перед записью. Ревизии и конфликты ответов работают как у обычной ссылки.
Права на публикацию, редактирование QA, произвольный HTTP, Jira/EVA и
администрирование через ключ не выдаются. Статусы задач в трекере он не меняет.

Адрес пакета в проектном подключении не содержит версии содержимого, поэтому
новые отчёты и обычные обновления сайта не требуют менять настройку клиента.
Смена или истечение самого ключа требуют новой команды подключения.

## Технические границы

Создание, список и отзыв: `/api/mcp/project-keys` (GET/POST),
`/api/mcp/project-keys/<key-id>` (DELETE), только с действующим входом автора.
Машинный API: `/api/mcp/projects/<key-id>/reports` и маршруты одного отчёта
`/<report-id>`, `/<report-id>/answers`, `/<report-id>/files/<file-id>`.
Секрет передаётся как `Authorization: Bearer`, не в URL. Хранится только его SHA-256
в таблице `shared_report_project_keys`; ключи обычных общих ссылок не раскрываются.
Ограничены маршруты, методы, размеры и частота запросов; список выдаётся страницами
до 50 отчётов. Отдельная проверка перед записью закрывает гонку с отзывом ключа
или переносом отчёта в другой проект. Обычные ссылки и временный приём сохраняются.

Проверки: `node --test tests/project-mcp.test.js` и браузерный сценарий
`node tests/project-mcp.browser.cjs` с Playwright в `QA_REPORT_PLAYWRIGHT`.

## Корпоративная версия

В корпоративной версии создание и отзыв
по-прежнему требуют корпоративного входа и CSRF; работа через отдельный проектный
ключ не зависит от срока браузерной сессии. Это отдельный вид доступа,
согласованный для опубликованных отчётов проекта. Вход и остальные API он не заменяет.
