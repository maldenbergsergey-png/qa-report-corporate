# Лимиты загрузки Jira

Файл размером 1 204 756 байт занимает 1 606 344 байта в base64, до добавления
полей JSON. Nginx с исходным лимитом `client_max_body_size 1m` отклонит такой
запрос кодом 413 до передачи в QA Report. Ручная загрузка в Jira проходит по
другому маршруту, поэтому может успешно работать с тем же файлом.

## Настройка сервера

В существующем HTTPS-блоке `server` именно QA Report установить:

```nginx
client_max_body_size 150m;
```

Если во вложенных `location` есть меньший `client_max_body_size`, его нужно
согласовать отдельно. Проверить все пути `/api/jira/attachments` и, для
публичной сборки, `/api/agent/jira/attachments`. Все внешние прокси и ingress
по пути также должны пропускать запрос. Корпоративный `deploy/nginx.conf`
уже содержит 150m; проверьте, что именно этот файл применяется на стенде.

На сервере администратор проверяет эффективную конфигурацию `sudo nginx -T`
(вывод может содержать настройки сервера, его не нужно публиковать), затем:

```sh
sudo nginx -t
sudo systemctl reload nginx
```

Перезагрузка допустима только после успешного `nginx -t`.
Существующие TLS, авторизация, заголовки и маршрутизация сохраняются.

`QA_REPORT_MAX_BODY_MB=150` означает 150 × 1024 × 1024 байт JSON.
`QA_REPORT_MAX_ATTACHMENT_MB=50` означает 50 × 1024 × 1024 байт одного файла.
Для 50 МиБ base64 занимает примерно 66,67 МиБ; нужен запас на JSON.
При увеличении файлового лимита до N байт тело запроса должно вмещать
`4 × ceil(N / 3)` плюс служебные поля. Не отключайте ограничения полностью:
данные файла пока собираются в памяти браузера и сервера.

## Проверка

После изменения конфигурации отправьте небольшой и затем проблемный файл
через QA Report в тестовую задачу. До этого можно проверить только прокси:
POST на `/api/health` с синтетическим телом должен дать JSON 405 от приложения,
а не HTML 413 Nginx. Этот метод healthcheck не сохраняет данные и не вызывает Jira.

Проверить настройки Jira можно через `GET /rest/api/2/attachment/meta` (Data
Center/Server) или `/rest/api/3/attachment/meta` (Cloud) с тем же подключением,
что используется для загрузки. `uploadLimit` — предел исходного файла в байтах;
`enabled: false` означает, что вложения отключены. Отдельно действуют разрешения
пользователя и ограничения прокси перед Jira. Метаданные не гарантируют наличие
всех разрешений или доступность диска.
