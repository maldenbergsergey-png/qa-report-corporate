# Локальный импорт файлов и результатов агента

## Импорт из Jira

В меню Jira выберите «Загрузить из Jira», затем «Ссылка на комментарий».
Переключатель «Импортировать с вложениями в этот браузер» включён по умолчанию.
С ним приложение скачивает оригиналы используемых изображений и файлов и
сохраняет их в исходных ячейках вместе с отчётом в IndexedDB. Облачное
хранилище для этого не требуется. При выключенном переключателе остаются
текст и подписи пропущенных вложений; внешние картинки не загружаются.

Для Jira Wiki поддерживаются `!screen.png!` и `[^report.pdf]`, в том числе во
вводном тексте. Скачиваются только вложения, используемые в импортируемом
отчёте. Повторные ссылки на один файл не вызывают повторную загрузку.
Одноимённые вложения без однозначного ID не выбираются наугад. Если файл
удалён, не найден или недоступен, приложение перечисляет ошибки и предлагает
продолжить с доступными файлами. Оригинальная ячейка сохраняет подпись ошибки.
Разметка сама по себе не содержит байты: при ручной вставке файла по одному
имени скачать его нельзя. Используйте ссылку на исходный комментарий.

Доступ к файлам проверяется через действующее подключение Jira: backend
получает список вложений задачи под текущими credentials и скачивает только
файл из этого списка. Произвольный URL от клиента не принимается.
Credentials не передаются на другой origin или по перенаправлению.
Лимит: 50 МБ на файл и 100 МБ суммарно на один импорт.

## Приём от агента

1. Откройте нужный отчёт и нажмите «ИИ» в шапке → «Включить приём».
2. Нажмите «Скопировать промпт». Передайте скопированные инструкции агенту,
   выполняющему проверки: в них есть временное подключение и контракт API.
3. Оставьте вкладку открытой. Когда фокус находится в редактируемой ячейке,
   применение результатов откладывается до выхода из неё.
4. После окончания нажмите «Остановить».

При включённом приёме подсвечены «Остановить» и «Скопировать промпт», а кнопка
включения недоступна. После остановки доступно только «Включить приём».
Индикатор ON/OFF на кнопке «ИИ» виден и при закрытом окне приёма.

Сессия действует 5 часов с момента включения приёма, привязана к одному отчёту и текущему владельцу.
В окне приёма отдельно от сообщений о пакетах показаны обратный отсчёт
и время отключения. Таймер учитывает реальное время, включая паузы
и пребывание вкладки в фоне; получение пакетов не продлевает подключение.

Можно включить приём максимум в трёх отчётах на пользователя: откройте каждый
и нажмите «Включить приём», затем передайте агенту отдельный промпт этого отчёта.
В промпте указаны отчёт и его собственное подключение. Переключение между
отчётами в той же вкладке не прекращает приём: фоновые результаты сохраняются
в свой отчёт и не меняют открытый. Другие подключения, их таймеры и кнопки
«Промпт» и «Остановить» доступны в этом же окне. Остановка отключает только
выбранный отчёт; лимиты памяти и количества сессий сервера сохраняются.
При перезагрузке вкладки все её подключения возобновляются до исходного срока.
Закрытая вкладка не может подтвердить
сохранение. Ключ подключения предоставляет только ограниченные операции этой
сессии и не заменяет вход пользователя или подключение Jira.

Включение приёма не включает облачную историю. Если облачная история уже
включена пользователем, её обычные правила синхронизации продолжают действовать.

## API для агента

Из подключения нужны `url`, `token` и `expiresAt`. Во **всех** запросах агента
передавайте `X-QA-Import-Token: <token>`. Ключ не передаётся в URL.
Запросы выполняет программа агента; модель не должна кодировать файлы в Base64.

`GET <url>/context` возвращает `reportId`, `expiresAt` и `context.sections`.
Каждый раздел содержит `id`, `columns` (`id`, `title`) и `rows`.
У строки есть `id`, `status` и `cells[columnId] = {text, hash}`. Получите контекст
до подготовки изменений: hash нужен для защиты параллельных правок пользователя.
Контекст не содержит бинарные файлы или credentials Jira.

`PUT <url>/files/<fileId>` загружает **сырые байты** одного файла:

```sh
curl --fail-with-body -X PUT "$QA_IMPORT_URL/files/shot-1" \
  -H "X-QA-Import-Token: $QA_IMPORT_TOKEN" \
  -H 'X-QA-File-Name: screenshot.png' \
  -H 'Content-Type: image/png' \
  --data-binary @screenshot.png
```

`X-QA-File-Name` — имя, закодированное через `encodeURIComponent`; для ASCII-имён
без пробелов кодирование не требуется. `fileId` и ID пакетов — уникальные строки
из латинских букв, цифр, `_` и `-` длиной до 80 символов. Ответ `201` содержит
`id`, `name`, `type`, `size`. Сервер проверяет сигнатуры отображаемых изображений;
прочие файлы отображаются как скачиваемые карточки.

`POST <url>/batches`, `Content-Type: application/json`:

```json
{
  "id": "result-1",
  "kind": "cells",
  "updates": [{
    "sectionId": "id-из-контекста",
    "rowId": "id-из-контекста",
    "columnId": "actual",
    "expectedHash": "hash-этой-ячейки-из-контекста",
    "text": "Форма открылась, данные совпадают с ожидаемыми.",
    "attachmentIds": ["shot-1"],
    "status": "OK"
  }]
}
```

`text` — обычный текст; он экранируется и заменяет всё содержимое целевой ячейки,
включая прежние вложения. Для дополнения текста используйте `mode: "append"`.
Чтобы только прикрепить файлы к существующему содержимому, опустите `text`.
`status` необязателен; возможные значения совпадают со статусами редактора.
Каждая ячейка указывается в пакете один раз. `expectedHash` обязателен и учитывает
также статус строки. Пакет применяется целиком; конфликт или отсутствующая
ячейка оставляют прежний отчёт без изменений.

Для полного чек-листа передайте:

```json
{
  "id": "checklist-1",
  "kind": "checklist",
  "format": "jira",
  "content": "||Проверка||Фактический результат||\n|Форма|Открылась !screenshot.png!|",
  "attachmentIds": ["shot-1"]
}
```

Имена в разметке должны точно совпадать с именами загруженных файлов.
При включённом приёме полный чек-лист автоматически заменяет содержимое
текущего отчёта без дополнительного подтверждения, в том числе при повторной
отправке исправленного чек-листа. Передавайте весь чек-лист, включая ранее
принятые данные: такой пакет не дополняет предыдущий. Для дозагрузки результатов
и файлов в существующие ячейки используйте `kind: "cells"` с актуальными
`expectedHash` из контекста. Проверка конфликтов ячеек сохраняется.

Обычный импорт через интерфейс и входящий импорт QA Assistant по-прежнему
запрашивают подтверждение перед заменой заполненного отчёта, даже когда приём
результатов от ИИ включён.

`GET <url>/batches/<batchId>` возвращает:

- `pending`: сервер принял пакет, браузер ещё не подтвердил сохранение;
- `saved`: текст, файлы и отметка пакета сохранены в IndexedDB;
- `rejected`: пакет не применён; `error` объясняет причину.

Успех — только `saved`. При сетевой ошибке повторите POST с **тем же ID и тем же
содержимым**: изменения не применятся второй раз. Другой payload с занятым ID
возвращает `409`. Исправленный после конфликта пакет должен иметь новый ID и
актуальные hashes. Если пакет отклонён, файлы для него необходимо загрузить
заново. После успешного сохранения контекст сессии обновляется.

### Поля отчёта: задача, окружение, итог и вводный текст

`context.metadata` содержит `issueUrl`, `environment`, `overallStatus` и `intro`.
У каждого поля есть `text` (текущее значение без HTML) и `hash`. Используйте
полученный hash без пересчёта: у вводного текста он учитывает форматирование.

Для изменения только полей отчёта отправьте:

```json
{
  "id": "report-details-1",
  "kind": "metadata",
  "metadata": {
    "issueUrl": {
      "value": "https://tasks.example.test/browse/QA-123",
      "expectedHash": "hash поля issueUrl из context.metadata"
    },
    "environment": {
      "value": "https://stage.example.test",
      "expectedHash": "hash поля environment из context.metadata"
    },
    "overallStatus": {
      "value": "НЕ ОК",
      "expectedHash": "hash поля overallStatus из context.metadata"
    },
    "intro": {
      "value": "Проверен build 8.\nОграничения: внешняя интеграция недоступна.",
      "expectedHash": "hash поля intro из context.metadata"
    }
  }
}
```

Передавайте только изменяемые поля. `metadata` также можно добавить к пакету
`cells` или `checklist`: поля и содержимое сохраняются атомарно; явные значения
полей имеют приоритет над значениями из разметки. Изменение любого переданного
поля пользователем после получения контекста отклоняет весь пакет. Редактирование
других полей не вызывает конфликт. Если курсор находится в ссылке на задачу,
окружении или выборе итога, применение пакетов ждёт выхода из поля.

`issueUrl` принимает HTTP(S)-ссылку без логина и пароля, ключ задачи или пустую
строку для очистки (до 4096 символов). Это ссылка на задачу, а не адрес самого
отчёта: его идентификатор и адрес сохраняются. `environment` — название
окружения или адрес стенда (до 4096 символов), пустая строка означает «Не указано».
`overallStatus` — один из статусов редактора: `OK`, `НЕ ОК`, `ПОЧТИ ОК`,
`НЕ ПРОВЕРЕНО`, `ЧАСТИЧНО ПРОВЕРЕНО`, `ТРЕБУЕТ УТОЧНЕНИЯ`.
`intro` — обычный текст с переносами строк, до 200 000 символов; HTML экранируется,
пустая строка очищает вводный текст. Остальные поля отчёта через `metadata`
недоступны. Старые пакеты без `metadata` продолжают работать.

После обновления приложения скопируйте промпт для агента заново: он содержит
новые поля и примеры. Если внешний профиль агента запрещает эти поля из-за
старого контракта API, обновите профиль по этой инструкции.


## Временные данные и ограничения

Новый канал агента хранит данные только в памяти Node-процесса. Он не пишет
файлы в SQLite, на диск, в MinIO или внешнее хранилище. После подтверждения
браузера, отклонения пакета, закрытия или истечения сессии временные файлы
удаляются. Перезапуск Node завершает сессии и удаляет неподтверждённые данные;
уже сохранённые браузером отчёты остаются на месте.

По умолчанию: 50 МБ на файл (серверный предел задаёт
`QA_REPORT_MAX_ATTACHMENT_MB`), 100 МБ файлов на сессию, 256 МБ временных данных
на процесс, до 64 файлов, 8 ожидающих пакетов и 128 пакетов за сессию.
JSON-запросы ограничены 1 МБ; в одном пакете не более 500 изменений ячеек.
До трёх одновременных сессий на владельца. Клиент не должен опрашивать статус
чаще одного раза в 2–3 секунды. Корпоративные общие rate limits сохраняются.

Маршруты браузера: `POST /api/local-import/sessions`,
`GET /api/local-import/sessions/<id>/next`,
`GET /api/local-import/sessions/<id>/files/<fileId>`,
`POST /api/local-import/sessions/<id>/ack`,
`DELETE /api/local-import/sessions/<id>`.
Они отделены от маршрутов агента и требуют отдельный reader key и identity
текущего пользователя. Не выдавайте reader key агенту. API-ответы и файлы не
кэшируются Service Worker. Не балансируйте одну сессию между независимыми
Node-процессами: для нескольких экземпляров нужна привязка сессии к экземпляру.
